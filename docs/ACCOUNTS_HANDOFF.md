# המשך העבודה על חשבונות LiveStocks

המסירה מתייחסת ל־14.11.2026. יש לבדוק `git status`, את הענף ואת הפריסה בפועל לפני המשך; קוד מקומי ובדיקות דמה אינם הוכחה למצב הייצור.

## ההחלטה המחייבת האחרונה

המשתמש אישר מעבר מ־Auth0 ל־Better Auth, כדי שטופסי אימייל וסיסמה יישארו בכתובת הקיימת `https://razmaz-live-stocks.vercel.app`. Google עדיין משתמש במסך האישור של Google. Supabase נשאר מסד הנתונים. נדרשת הרשמה פתוחה, אימות אימייל, איפוס סיסמה ובידוד מלא לפי משתמש.

אין לאחד חשבונות באמצעות התאמת אימייל בלבד. התאמת כתובות מאומתות מציעה קישור; שני אימותים טריים ונפרדים והסכמה מפורשת נדרשים לפני איחוד נתונים. מזהה התיק הקנוני נשאר יציב; כל ספר עסקאות FIFO נשמר בנפרד גם כשיש אותה מניה באותו בנק. אין למחוק או להסיר עסקאות שנראות דומות.

## מה כבר קיים בקוד

- טפסים בעברית ובאנגלית לכניסה, הרשמה, בקשת שחזור, קביעת סיסמה ואימות אימייל. תמיכה במצב בהיר וכהה ובמובייל.
- Better Auth ושרת OAuth עם גרסאות נעולות, טוקנים נפרדים לאתר ול־MCP, PKCE, יעד הרשאה קבוע ולקוח MCP מנהלי קבוע. רישום לקוחות דינמי כבוי.
- אחסון אימות בסכמת PostgreSQL שאינה חשופה ל־Data API, באמצעות תפקיד שרת מוגבל. הגדרות SMTP חסרות גורמות לכשל מפורש; אין משלוח מדומה בייצור.
- אימות JWT יחד עם בדיקת session והרשאת OAuth חיות במסד. חתימה או `iat` חדשים לבדם אינם מחזירים הרשאה שנשללה.
- מסד עם מזהה תיק קנוני, מיפוי זהויות, הקפאת כתיבה, RPC לאיחוד בשלבים, היסטוריית הרשומות המקוריות ושמירת מפתחות מוצפנים.
- ממשק סקירה ואישור איחוד, חוזה טיפוסים ובדיקות. **ה־API הציבורי לאיחוד עדיין כבוי:** `/api/account/link/status` מחזיר `available:false`. אימותי הבעלות והעובד שמנהל את שלבי האיחוד טרם חוברו.
- קריאת ווידג׳ט אטומית: זיהוי מפתח, הרשאות, נתונים ומפתח שוק מוצפן נקראים תחת אותה נעילה. אין קריאה מנהלית מאוחרת שעלולה לכלול תיק שזה עתה אוחד.

## מה לא הושלם

1. **הפעלת שירות האימות בענן:** אישורי מסד ייעודיים ומשתני Better Auth, משלוח אימייל אמיתי, כתובות חזרה חדשות של Google, לקוח MCP קבוע, מסך הסכמת OAuth, ו־Supabase Custom OIDC עם issuer של האתר. אין להסיק שגרסת ניסיון של Auth0 מספקת יכולת קבועה.
2. **שרת האיחוד:** endpoints לחוזה הממשק, הצעות מזהים אטומים, שני אימותים טריים, סקירה מדויקת, בחירת הגדרות ומפתח, עובד עמיד לכשל ולניסיון חוזר, ביטול sessions/הרשאות והפעלת החשבון רק אחרי כל הבדיקות. לשמור מקור AAD בהיסטוריית מפתחות ולהצפין מחדש עבור התיק הקנוני.
3. **אינטגרציה בפועל:** חיבור OAuth בתוך ChatGPT עם ה־App הקיים, חידוש וביטול, כתובת החזרה האמיתית, Google אמיתי, אימייל אמיתי, ו־iPhone פיזי. מסך הסכמת MCP `/oauth/consent` עדיין נדרש.
4. **מעבר הייצור:** נדרש גיבוי סופי מוצפן, שחזור וחזרה על חבילת המיגרציות המלאה; אישור מפורש של זהות Better Auth החדשה לצד הבעלות הקודמת; חלון תחזוקה, חסימת הכתובות הישנות, העברה אטומית והשוואת כל נתוני המקור. `scripts/cutover-personal-accounts.mjs --prepare` חסום בכוונה עד להשלמת התנאים. אסור להפעיל את חבילת ה־SQL הישנה.
5. **הפצה:** עדכון חבילת הפלאגין עם שמירת המזהים; הכנת חבילת הגשה ציבורית, הגשה ואישור הם שלבים נפרדים. עדכון README, מדיניות וצילומי דמה לאחר שינוי הזרימה הסופי.
