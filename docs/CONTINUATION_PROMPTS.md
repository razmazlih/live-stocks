# פרומפטים לשיחות המשך

עדכון: **15.11.2026**. האתר, Google הציבורי, האיחוד הכללי והחיבור הפרטי החדש ל־ChatGPT כבר פעילים. החלפת מפתח Finnhub אומתה: המפתח החדש פעיל והישן נדחה. אין להפעיל מחדש את מעבר הבעלות, להכין מאגר אימות חדש או להתקין שוב את הפלאגין הישן. קראו תחילה את [מסמך המצב](ACCOUNTS_HANDOFF.md), ואמתו שהמצב לא השתנה מאז.

## 1. בדיקת Scriptable על iPhone פיזי

```text
המשך את LiveStocks. קרא docs/ACCOUNTS_HANDOFF.md ו-output/widget/README.md; השתמש במקור output/widget/Stocks Status.js ואמת את הגרסה הנוכחית. בדיקת API הווידג'ט בייצור כבר עברה 25/25, כולל ביטול, תפוגה וניקוי; המשימה שנותרה היא הוכחה על מכשיר אמיתי.

תאם עם המשתמש גישה ל-iPhone ול-Scriptable. הפק מפתח אישי דרך הגדרות החשבון ושמור אותו רק דרך תהליך Keychain שבסקריפט. אין להכניס מפתח לקוד, לפרמטרי הווידג'ט, לצ'אט או לקובץ iCloud. אמת תצוגה בעברית/אנגלית ובהיר/כהה, בגדלים הרלוונטיים, רענון, חזרה לאפליקציה ומצב לא מקוון באותו חשבון. בדוק ש-401/403 מבטלים מטמון ולא מציגים נתוני תיק ישנים.

אל תשנה או תמחק רשומות פיננסיות. נקה רק מפתחות בדיקה שנוצרו במפורש למשימה. אל תשמור צילומי תיק אמיתי ב-README או בחומרי פרסום; השתמש בנתונים סינתטיים לתיעוד ציבורי. דווח בנפרד מה הוכח במכשיר, מה הוכח רק בסימולציה ומה עדיין לא נבדק. אם אין מכשיר זמין, תעד זאת בלי לטעון שהבדיקה הושלמה.
```

## 2. השלמת הכנת ההגשה הציבורית

```text
המשך את LiveStocks תוך שימוש במיומנות prepare-plugin-submission ובמקורות החבילות הקיימים. קרא docs/ACCOUNTS_HANDOFF.md, docs/CHATGPT_ACTIVATION.md ו-plugins/livestocks/PUBLIC_RELEASE.md; בדוק גם plugins/livestocks-oauth ואת טיוטת ההגשה הקיימת. אל תיצור מחדש App או plugin.

החיבור הפרטי הפעיל הוא LiveStocks (OAuth), plugin_asdk_app_6af9b5f79fe48191a12eaa9c67d6ae7b וה-App התואם asdk_app_6af9b5f79fe48191a12eaa9c67d6ae7b. שבעת הכלים ומיומנות הניתוח 1.1.0 אומתו, כולל קריאה, refresh, ביטול וחיבור מחדש. המשתמש ביקש להסיר את ההתקנה הישנה והיא הוסרה; ארטיפקט הענן הישן והמקור נשמרו. אין להתקין את הישן מחדש.

השלם רק את החסרים להגשה לפי הדרישות העדכניות: התאמת טיוטת החבילה לחיבור OAuth הפעיל, metadata, אייקונים קיימים, קישורי מדיניות, מקרי סקירה, הדגמה סינתטית וגישה מוגבלת לסוקר לפי כללי המארח. אל תמציא זהות מפתח מאומתת, פרטי חברה, מדינות יעד, סרטון או אישור סקירה. הרשאות נשארות לקריאה בלבד; אין מסחר ואין רישום לקוחות דינמי.

הכן תוצאה קונקרטית לבדיקה, עם קומיטים ממוקדים ו-README עדכני. אל תעלה, תגיש או תפרסם בלי הרשאה מפורשת לפעולה הרלוונטית. חיבור פרטי עובד, הכנת ZIP, הגשה ואישור ציבורי הם שלבים שונים; דווח במדויק איזה מהם הושלם.
```

## 3. תחזוקה ובדיקות עתידיות

```text
תחזק את LiveStocks לפי התקלה או השינוי המבוקשים, בלי לחזור על מעבר החשבונות שכבר בוצע. קרא docs/ACCOUNTS_HANDOFF.md, docs/ACCOUNT_LINKING.md ואת דוחות האימות הרלוונטיים. אמת Git, alias קנוני, הגדרות סביבת היעד ומצב ענן; לשינויים מקבילים הקצה worktree וענף codex נפרדים ובעלים יחיד לכל משאב.

מצב הבסיס: Google בלבד, Better Auth עם session/approval חיים, Supabase עם RLS, איחוד כללי מאושר ומופעל בייצור, עובד מאומת יומי ב-04:00 UTC וחיבור OAuth פרטי חדש שעבר מחזור חיים במארח. סיסמאות ו-SMTP כבויים. כניסת הבעלים והתיק הקיים אומתו אנושית; המשתמש ויתר במפורש על בדיקה אנושית עם Google שני. אין להציג את הוויתור כהוכחה שבדיקה זו בוצעה או לדרוש אותה מחדש כחסם כללי.

שמרו את כל הרשומות, המזהים, חותמות הזמן וספרי FIFO. אל תערכו מיגרציות שכבר הוחלו; שינוי DB חדש מחייב מיגרציה נפרדת, גיבוי ובדיקות מתאימות. אל תחזירו הרשאות אנונימיות, תחלישו PKCE/audience/resource/client או תעקפו אישור מפורש לאיחוד. בבדיקת פונקציות SECURITY DEFINER בדקו הרשאות אפקטיביות לכל החתימות, לא רק טקסט REVOKE; לתפקיד מנוהל עשוי להיות SET ROLE בלי INHERIT.

הריצו בדיקות ממוקדות לשינוי, ואת מסלולי PostgreSQL המקומיים כאשר משתנים אימות, הרשאות או איחוד. בדיקות native מדולגות בחבילה הרגילה ומורצות בנפרד. אשרו כשל/חידוש, תפוגה, ביטול ושימור נתונים לפני הרחבת פריסה. אין צורך להשהות שירותי ענן אם הבעיה ניתנת לבדיקה מקומית; אישור חלון השהיה קודם אינו תקף לחלון חדש. סיימו בקומיטים, תיעוד והוכחות מדויקות, בלי סודות ובלי נתוני תיק ציבוריים.
```
