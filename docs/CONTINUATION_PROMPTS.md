# פרומפטים לשיחות המשך

עדכון: 15.11.2026. ארבע משימות נפרדות; אין להריץ אותן כארבעה מפעילי ענן מתחרים. עבודות 1 ו־4 חייבות לתאם בעלות על שירותי הענן והפריסה. עבודה 2 אינה תנאי לכניסה חוזרת עם אותה זהות Google. עבודה 3 יכולה להכין בדיקות וחומרי הגשה, אך האימות החי הסופי תלוי בפריסה המאושרת.

## 1. השלמת הוכחת הענן והתחברות Google

```text
המשך את LiveStocks מהענף codex/personal-accounts-oauth-gate. קרא docs/ACCOUNTS_HANDOFF.md, docs/BETTER_AUTH_SETUP.md ו-docs/HOSTED_AUTH_GATE.md; אמת Git ומצב ענן עדכני וצור worktree וענף codex נפרדים. תאם בעלות אחת על המשאבים עם מפעיל המעבר.

החלטת ההשקה היא Google בלבד באמצעות Better Auth: אין להפעיל הרשמת סיסמה, SMTP או Brevo. מסך ההסכמה, הלקוח הקבוע וזריעתו, טפסי האתר ובדיקות session/approval כבר ממומשים. מאגר האימות הסופי בייצור כבר הוכן עם 13 טבלאות ותפקיד מוגבל; אין להכינו מחדש ואין להעביר בעלות פיננסית במשימה זו.

השלם את בדיקת הענן המבודדת שנעצרה: אמת קודם מוכנות discovery/JWKS וכתובת ה-issuer, ואז Supabase TPA, חתימה/role, שני משתמשים סינתטיים, בידוד RLS, כתיבה באתר בלבד, MCP לקריאה בלבד, חידוש וביטול session/approval. תקן את כלי הבדיקה או את הסיבה המוכחת לכשל בלי להחליש audience/resource/client/PKCE או להשתמש ב-service role כתחליף לבידוד. אין לאפס נתונים קיימים או להשתמש שוב באישור השהיה שפג. החזר cleaner למצב תקין וסגור משאבי בדיקה לפי החלון המאושר.

לאחר הוכחת הענן, תאם עם מפעיל המעבר את הכנת תחזוקה/TPA ואת כניסת Google האנושית המאוחרת לצורך receipt הבעלות בן 15 דקות. שמור אותה זהות משתמש בכניסות חוזרות. בדוק עברית/אנגלית, כהה ומובייל בלי לחשוף נתוני תיק. סיים בקומיטים ממוקדים ובהוכחות נפרדות למקומי, hosted ו-Google אנושי; אל תציג READY כהוכחת אינטגרציה.
```

## 2. השלמת איחוד בין שני תיקים קיימים

```text
המשך את LiveStocks מהענף codex/personal-accounts-oauth-gate. קרא docs/ACCOUNTS_HANDOFF.md, docs/CANONICAL_ACCOUNT_MERGE.md, docs/ACCOUNT_LINKING_UI.md ו-types/account-linking.ts. אמת Git וצור worktree וענף codex נפרדים.

כניסה חוזרת עם אותו Google כבר משתמשת באותו משתמש, וקישור שיטות כניסה בטוח כבר קיים. משימה זו היא רק איחוד שני תיקים נפרדים: חבר את הוכחות השליטה והעובד העמיד לחוזה הממשק ול-RPC הקיימים. ה-API הכללי כבוי כרגע; הפעל אותו רק אחרי הוכחות ובדיקות. התאמת אימייל מאומת מציעה מועמד, אך אינה הרשאה: נדרשים שני אימותים טריים ונפרדים, סקירה, בחירת הגדרות/מפתח ואישור מפורש.

שמור כל מזהה, ערך, חותמת זמן וספר FIFO נפרד; אין למחוק עסקאות דומות או לאחד lots של פוזיציות כפולות. השתמש בגדר הכתיבה ובשלבי האיחוד הקיימים, שמור AAD מקורי בארכיון המפתחות והצפן מחדש לבעלים הקנוני. בדוק idempotency, כשל בכל שלב, חידוש עבודה, מרוצים מול כתיבה/refresh וחסימת JWT ישן באמצעות session/approval חיים. השתמש בחישובי החשבונאות האמיתיים ובמחירים קבועים להוכחת שימור.

אל תשנה את ארבע המיגרציות הנעולות ואל תבצע איחוד או העברת תיק אמיתי. תאם מיגרציה נוספת אם תידרש. השאר את ההשקה Google-only; אין להוסיף SMTP. מסור קומיטים, בדיקות וחסימות מדויקות, בלי לשכפל את כלי המעבר או את קישור שיטות הכניסה.
```

## 3. אימות ChatGPT, ווידג׳ט והגשה

```text
המשך את LiveStocks מהענף codex/personal-accounts-oauth-gate. קרא docs/ACCOUNTS_HANDOFF.md, docs/BETTER_AUTH_SETUP.md ו-plugins/livestocks/README.md; אמת Git וצור worktree וענף codex נפרדים.

מסך /oauth/consent, זריעת לקוח MCP קבוע ומימוש OAuth כבר קיימים. השלם הוכחת חיבור בפועל של ה-App והפלאגין הקיימים, תוך שמירת מזהיהם: כתובת חזרה אמיתית, כניסת Google, אישור/סירוב, דרישות OIDC של ChatGPT, חידוש, ביטול וחיבור מחדש. שמור MCP לקריאה בלבד; ביטול חייב לחסום access JWT שכבר הונפק ו-refresh ישן. אין להחליש audience/resource/client/PKCE ואין להפעיל רישום לקוחות דינמי. תאם בדיקה חיה עם מפעיל הפריסה; קוד או discovery לבדם אינם הוכחה לחיבור ChatGPT.

בדוק ווידג׳ט Scriptable עם מפתח אישי תקף, פג ומבוטל, תפוגת 90 יום ו-Keychain. שמור snapshot אטומי ובדיקת תוקף לפני תשובה. הפרד סימולציה מהוכחה על iPhone פיזי. חומרי ההדגמה וחשבון הבדיקה יהיו סינתטיים בלבד. בדוק קודם את טיוטת ההגשה הקיימת והשלם רק חסרים לפי מיומנות ההגשה; הכנת חבילה, הגשה ואישור פרסום הם שלבים נפרדים.

אין להעביר נתוני ייצור או לשנות את מאגר האימות/מיגרציות במסגרת המשימה. סיים בקומיטים ודו״ח שמפריד מה אומת בפועל, מה ממתין לפריסה ומה דורש מכשיר או אישור מארח.
```

## 4. מעבר מבוקר לייצור ושיוך התיק המקורי

```text
קבל בעלות יחידה על מעבר הייצור של LiveStocks. קרא docs/ACCOUNTS_HANDOFF.md, docs/PERSONAL_ACCOUNT_CUTOVER.md ואת הוכחת full-bundle-restore-2026-11-15.json. אמת מצב Git, פריסות, ענן ואישורים לפני פעולה. אל תשתמש ב-SQL ישן ואל תערוך את ארבע המיגרציות הנעולות.

כלי המעבר המלא, אימוץ מאגר האימות ושחזור מוצפן עם rollback כבר ממומשים ונבדקו מקומית; אין לבנות אותם מחדש. מאגר האימות הסופי בלבד כבר נוצר בייצור, ללא שינוי פיננסי. CUTOVER_READY=false כי הוכחת hosted TPA והבעלים האמיתי טרם הושלמו. פריסת READY לא מקודמת עברה discovery/JWKS ו-503 פיננסי; אמת מחדש את ה-alias הפעיל והגדרות maintenance, אל תניח שקוד חדש כבר הוגש למשתמשים.

לאחר הוכחת ענן, הכן תחזוקה ו-TPA, ואז בצע כניסת Google אנושית ואישור מפורש בכלי המקומי המחובר למאגר הסופי. זהות Auth0 המקורית נשארת מזהה התיק; receipt חתום בן 15 דקות קושר את זהות Better Auth המדויקת. אין לבחור לפי אימייל או נרשם ראשון, אין לייבא משתמש חדש אחר ואין צורך לחדש Auth0. ודא שיש זמן לגיבוי ולשחזור לפני תפוגת ה-receipt.

פעל לפי סדר הכלי: סגירת פריסות ישנות ומטמונים, freeze וניקוז, גיבוי סופי מוצפן של ארבע הסכמות כולל auth, שחזור והוכחה מול המקורות הנוכחיים, ואז עסקה אחת עם אימוץ מדויק, השוואת כל ששת ה-digests תחת נעילות וארבע רשומות migration history. שמור IDs, חותמות זמן, ערכים ומפתחות מוצפנים. שינוי readiness ייעשה רק לאחר הוכחות אמיתיות וביקורת החבילה; אין --apply אוטומטי ואין חזרה להרשאות אנונימיות במקרה כשל.

לאחר commit אמת בעלים ושני חשבונות, אתר/API/MCP/ווידג׳ט והרשאות/ביטול, ורק אז פתח את הפריסה. תאם טיפול במפתח Finnhub הישן בלי לפגוע בשחזור. ודא cleaner תקין; אישור השהיה קודם אינו אישור לחלון חדש. השלם קומיטים, README ודו״ח סופי שמפריד מוכנות, ביצוע והוכחה, ללא סודות או נתוני תיק.
```
