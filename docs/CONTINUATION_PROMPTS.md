# פרומפטים לשיחות המשך

להדביק כל פרומפט בשיחה נפרדת באותו פרויקט. עבודה 4 תלויה בהשלמת העבודות הרלוונטיות לפניה. כל שיחה צריכה לקרוא קודם את מצב המסירה ולא להניח שהקוד המקומי כבר פעיל בייצור.

## 1. השלמת והפעלת ההתחברות בתוך האתר

```text
המשך את LiveStocks מהענף codex/personal-accounts-oauth-gate. קרא קודם docs/ACCOUNTS_HANDOFF.md ואת docs/BETTER_AUTH_SETUP.md, אמת מצב Git ופריסה, וצור worktree וענף codex נפרדים.

המשתמש אישר Better Auth במקום Auth0 כדי שכל טופסי האימייל והסיסמה יישארו בכתובת האתר הקיימת. השלם מסלול עובד של הרשמה, אימות אימייל, כניסה, איפוס, יציאה ו-Google. חבר משלוח אימייל אמיתי, סודות ותפקיד מסד ייעודי ומוגבל, ואמת JWT של האתר ושל MCP מול Supabase Custom OIDC בסביבה מבודדת. בדוק Safari/Chromium, עברית/אנגלית, מצב כהה ומובייל. שמור הגנות CSRF, session חי, מפתחות פרטיים ורישום לקוחות קבוע; אין להשתמש ב-ROPG או בגישה מנהלית רגילה לנתוני התיק. אל תדמה משלוח מוצלח כש-SMTP חסר.

הנתונים האמיתיים עדיין לא הועברו. תאם מיגרציות עם עבודת האיחוד והשאר את מעבר הייצור לעבודה הייעודית. השלם קומיטים, README, צילומי דמה ודו״ח בדיקות עם חסימות מדויקות.
```

## 2. איחוד חשבונות ושמירת כל הנתונים

```text
המשך את LiveStocks מהענף codex/personal-accounts-oauth-gate. קרא docs/ACCOUNTS_HANDOFF.md, docs/CANONICAL_ACCOUNT_MERGE.md, docs/ACCOUNT_LINKING_UI.md ו-types/account-linking.ts. אמת Git וצור worktree וענף codex נפרדים.

חבר את שרת האיחוד לממשק הקיים: זיהוי מועמדים באמצעות אימייל מאומת, שני אימותים טריים ונפרדים, סקירת נתונים ובחירת הגדרות/מפתח, אישור מפורש ועובד עמיד לחידוש אחרי כשל. ה-API כבוי כרגע; הפעל אותו רק אחרי הבדיקות. אימייל לבדו אינו הרשאה. השתמש ב-RPC המוקפא והאטומי הקיים, שמור מזהי פוזיציות/עסקאות, כל ערכי המקור וחותמות הזמן. אין לערבב FIFO של פוזיציות כפולות ואין למחוק עסקאות דומות. שמור היסטוריית מפתחות מוצפנים עם AAD המקורי והצפן מחדש לבעלים הקנוני.

בדוק איחוד חוזר, מרוצים מול כתיבה וחידוש טוקנים, מניעת קריאה ישנה אחרי איחוד, חסימת כתיבה של MCP ושמירת החישובים עם מחירים קבועים. השתמש בסשנים והרשאות Better Auth חיות, ולא ב-iat בלבד. תעד מה נבדק מקומית ובענן; אין להעביר את התיק האמיתי במסגרת עבודה זו. צור קומיטים ותיעוד ברורים.
```

## 3. הפלאגין, הווידג׳ט וחבילת הפרסום

```text
המשך את LiveStocks מהענף codex/personal-accounts-oauth-gate. קרא docs/ACCOUNTS_HANDOFF.md, docs/BETTER_AUTH_SETUP.md ו-plugins/livestocks/README.md. אמת Git וצור worktree וענף codex נפרדים.

השלם את חיבור OAuth של ה-App והפלאגין הקיימים ל-Better Auth, כולל מסך /oauth/consent, הלקוח הקבוע וכתובת החזרה האמיתית של ChatGPT. שמור את מזהי ה-App והפלאגין ואת הרשאות הקריאה בלבד. בדוק כניסה, סירוב, ID token לפי דרישות המארח, חידוש, ביטול הרשאה וחיבור מחדש בפועל; שלילה חייבת לחסום גם JWT שכבר הונפק וגם refresh ישן. אין להחליש בדיקות resource, audience, client או PKCE.

השלם אימות ווידג׳ט Scriptable עם מפתח אישי תקף/פג/מבוטל, תפוגת 90 יום ו-Keychain. שמור קריאה אטומית של snapshot תחת נעילת בעלים. הפרד בדיקות מדומות מבדיקה על iPhone פיזי. השתמש בנתוני דמה בלבד בחומרי פרסום והכן חבילת הגשה עם הדגמה וחשבון בדיקה סינתטי לפי מיומנות הגשת פלאגינים. הכנת החבילה, הגשה ואישור פרסום הם שלבים נפרדים. אל תעביר נתוני ייצור במסגרת העבודה; תאם את הבדיקה הסופית לאחר הפריסה הייעודית. צור קומיטים ודו״ח אימות.
```

## 4. מעבר בטוח לייצור והעברת התיק הקיים

```text
קבל בעלות על שלב המסירה האחרון של LiveStocks. קרא קודם docs/ACCOUNTS_HANDOFF.md ואת docs/PERSONAL_ACCOUNT_CUTOVER.md, אמת Git/פריסה/מסד בפועל ואחד את תוצאות שיחות ההתחברות, האיחוד והפלאגין. אל תפעיל SQL מהחבילה הישנה: מחולל המעבר חסום כי היא אינה כוללת את הדרישות החדשות.

לאחר שכל הבדיקות הנדרשות עוברות, אמת במפורש את חשבון Better Auth המיועד להעברת התיק ואת הקשר לזהות Auth0 שאושרה קודם. אין לבחור לפי אימייל או לפי הנרשם הראשון. הכן חבילת מיגרציות מלאה בעסקה אחת, גיבוי מוצפן מחוץ ל-Git ובדיקת שחזור, וחזרה על נתוני דמה ועל שחזור התיק עם כשל מכוון. שמור מזהים, היסטוריה, חותמות זמן וערכים פיננסיים; השווה נתוני מקור וחישובים במחירים קבועים.

בצע חלון תחזוקה מבוקר שסוגר גם פריסות ישנות ומטמונים, גיבוי סופי לאחר חסימת כתיבה, שיוך בעלות והרשאות RLS, ואז אימות ופתיחה. אין להחזיר הרשאות ציבוריות גם אם צריך לתקן. החלף את מפתח Finnhub שנחשף בהגדרות הישנות ושמור אותו מוצפן בחשבון הנכון. בדוק אתר, API, ChatGPT וווידג׳ט מול שני חשבונות. ודא ש-cleaner פעיל; אישור ההשהיה הישן כבר מומש והסתיים. שמור אישורים קיימים, בצע קומיטים מסודרים ועדכן README ודו״ח סופי ללא סודות.
```
