# רישום עסקאות שכבר בוצעו, מתוך ChatGPT

מספרים ב־ChatGPT מה קניתם או מכרתם, והצ׳אט מכין כרטיס עם הפרטים והשפעתם על התיק. אפשר לכלול עד 25 עסקאות בכרטיס אחד, גם קניות ומכירות של מניות שונות ובחשבונות שונים. לחיצה אחת שומרת את כל העסקאות בכרטיס ומציגה את התיק המעודכן. אפשר למסור פרטים בשיחה או לצרף צילום אישור ביצוע או רשימת עסקאות. צילום יתרות דורש השלמה של פרטי הביצוע בפועל.

## מה מספרים לצ׳אט

לכל עסקה מציינים סוג פעולה, סימול, כמות, מחיר ביצוע למניה בדולר ותאריך. כשיש כמה חשבונות, מציינים באיזה מהם בוצעה כל עסקה. אם יש רק מקור פעיל אחד, הוא נבחר אוטומטית. הצ׳אט שואל רק על פרטים חסרים.

לפני הכנת הכרטיס נדרשת עמלה ידועה בדולרים, או אמירה מפורשת שלא הייתה עמלה (0). כשחסר הנתון הצ׳אט שואל עליו; אין לשלוח עמלה לא ידועה או להניח אפס. רשומות היסטוריות עם עמלה לא ידועה נשמרות ללא שינוי עד לתיקון מפורש באתר: החזקות → ניהול היסטוריה → עריכת העסקה. עריכת שדה אחר אינה הופכת עמלה לא ידועה לאפס.

זו רשומה של עסקה שכבר בוצעה, לא הוראה לברוקר. מותר לרשום קנייה למניה קיימת או מכירה חלקית. מגבלות המלצות ההשקעה — קנייה של מניה חדשה בלבד ומכירה מלאה — אינן משתנות.

## אישור והרשאות

`prepare_chat_transaction` מכין הצעה ל־15 דקות. בסכמת הכלי ב־ChatGPT שולחים `{ "transactions": [...] }` בקריאה אחת, גם לעסקה בודדת. השרת מקבל גם את מבנה השדות הקודם של עסקה יחידה לתאימות עם גרסאות ישנות. הצעה חדשה מחליפה את ההצעה הקודמת הממתינה באותו חיבור, לכן כשיש מעל 25 עסקאות מאשרים כל כרטיס לפני הכנת הכרטיס הבא. בעת ההכנה התיק נשאר במצבו הקיים. בפעם הראשונה המשתמש מאשר דרך החיבור הקיים את הרשאת OAuth `portfolio:transactions` לצד `portfolio:read`.

רק כפתור הכרטיס יכול לקרוא `confirm_chat_transaction` עם יכולת אישור פרטית. הודעת ״מאשר״ בצ׳אט אינה תחליף לכפתור. `review_chat_transaction` קורא את ההצעה המדויקת; `cancel_chat_transaction` מבטל אותה בלי שינוי בתיק. היכולת אינה מופיעה בתוכן למודל, ב־DOM, באחסון דפדפן או בלוגים.

ההצעה קשורה לבעלים, לחשבון OAuth, לסשן, ללקוח ולאישור ההרשאה. השמירה בודקת מחדש את טביעת התיק ואת פרטי ההצעה. כל העסקאות בכרטיס נשמרות יחד. אם עסקה אחת נדחית, הקבוצה כולה נשארת ללא רישום. שינוי תיק, פקיעת הצעה, החלפה או הרשאה שאינה מתאימה מונעים שמירה. אישור חוזר לאותה הצעה מחזיר את הקבלה הקיימת.

## היסטוריה וחישובים

כל ביצוע נשמר כרשומת BUY או SELL רגילה לצד העסקאות הקיימות. מכירה חייבת להיות מכוסה בכמות מניות מספקת בתאריך הביצוע. הוספת עסקה היסטורית נבדקת באמצעות שחזור FIFO מלא, לרבות צילומי מצב מאוחרים. אם צילום מצב מאוחר קובע את היתרה היום, תוצג אזהרה שהוספת ההיסטוריה לא בהכרח משנה אותה. עסקאות בכרטיס מסודרות מהתאריך הישן לחדש. עסקאות מתאריך זהה נשמרות אחרי הרשומות הקיימות לאותו יום ובסדר שבו נשלחו. גבול ״היום״ נקבע לפי Asia/Jerusalem.

אחרי השמירה קוראים מחדש את כל ההחזקות הפתוחות, כולל חשבונות שלא השתנו. קריאת הרענון מוגבלת לחמש שניות. כישלון רענון אינו הופך שמירה מאומתת לכישלון, ואינו מבצע כתיבה נוספת. בכרטיס מוצגות כמויות ועלויות קנייה; אין המצאת מחירי שוק או רווח נוכחי.

## בדיקות ושחזור מקומי

```sh
npx vitest run __tests__/chat-transactions.test.ts __tests__/chat-transaction-server.test.ts __tests__/chat-sync-app.test.ts __tests__/investment-mcp.test.ts
python3 scripts/test-chat-transactions-postgres.py
node scripts/preview-chat-review.mjs buy
node scripts/preview-chat-review.mjs sell
node scripts/preview-chat-review.mjs screenshot
```

בדיקת PostgreSQL יוצרת מסד מקומי זמני ומסירה אותו בסיום. היא בודקת הרשאות, אי־שינוי לפני אישור, בידוד משתמשים וסשנים, יכולת אישור, קנייה, מכירה חלקית ומלאה, FIFO, היסטוריה, אישור חוזר, פקיעה, תמימות הסקירה וסמכויות תפקיד מוגבל. קובצי התצוגה נוצרים ב־`output/playwright/` ומשתמשים רק בנתוני הדגמה ללא רשת או כתיבה לתיק אמיתי.
