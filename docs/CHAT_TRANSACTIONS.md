# רישום עסקאות שכבר בוצעו, מתוך ChatGPT

אפשר לעדכן את LiveStocks גם בשיחה, בלי צילום מסך. מספרים מה קניתם או מכרתם, והצ׳אט מכין כרטיס עם הפרטים והשפעתם על התיק. לחיצה על האישור שומרת את העסקה ומציגה את התיק שנקרא מחדש מהשרת.

## מה מספרים לצ׳אט

צריך סוג פעולה, סימול ברור, כמות, מחיר ביצוע למניה בדולר ותאריך. כשיש כמה חשבונות, מציינים באיזה מהם. אם יש רק מקור פעיל אחד, הוא נבחר אוטומטית. הצ׳אט שואל רק על פרטים חסרים. מחיר עכשווי אינו מחיר ביצוע, ותאריך לא ברור לא מושלם אוטומטית.

אפשר למסור עמלה, אבל היא אינה מעכבת שמירה. עמלה שלא נמסרה נשמרת כלא ידועה; אמירה מפורשת שלא הייתה עמלה נשמרת כאפס. סכומי עלות ורווח שאינם שלמים מסומנים כך, בלי להמציא עמלה. באתר: החזקות → ניהול היסטוריה → עריכת העסקה מאפשרים להזין עמלה או לאשר שלא נגבתה. עריכת שדה אחר אינה הופכת עמלה לא ידועה לאפס.

זו רשומה של עסקה שכבר בוצעה, לא הוראה לברוקר. מותר לרשום קנייה למניה קיימת או מכירה חלקית. מגבלות המלצות ההשקעה — קנייה של מניה חדשה בלבד ומכירה מלאה — אינן משתנות.

## אישור והרשאות

`prepare_chat_transaction` מכין הצעה ל־15 דקות ואינו משנה החזקות. נדרשת הרשאת OAuth נפרדת `portfolio:transactions` לצד `portfolio:read`; הרשאת `portfolio:sync` נשארת מוגבלת לעדכוני צילום מצב. פרסום גרסה או הרחבת תקרת הלקוח אינם משדרגים אישורים קיימים. המשתמש מאשר את ההרשאה בפעם הראשונה דרך החיבור הקיים.

רק כפתור הכרטיס יכול לקרוא `confirm_chat_transaction` עם יכולת אישור פרטית. הודעת ״מאשר״ בצ׳אט אינה תחליף לכפתור. `review_chat_transaction` קורא את ההצעה המדויקת; `cancel_chat_transaction` מבטל אותה בלי שינוי בתיק. היכולת אינה מופיעה בתוכן למודל, ב־DOM, באחסון דפדפן או בלוגים.

ההצעה קשורה לבעלים, לחשבון OAuth, לסשן, ללקוח ולאישור ההרשאה. שמירה בודקת מחדש את טביעת התיק ואת הצעת הסקירה. שינוי תיק, פקיעת הצעה, החלפה או הרשאה שאינה מתאימה מונעים שמירה. אישור חוזר לאותה הצעה מחזיר קבלה קיימת בלי להוסיף עסקה.

## היסטוריה וחישובים

נשמרות רשומות BUY/SELL אמיתיות, לא נקודות RECONCILE מדומות. עסקאות קודמות אינן נמחקות או נכתבות מחדש. מכירה אינה יכולה ליצור יתרה שלילית בתאריך כלשהו. הוספת עסקה היסטורית נבדקת באמצעות שחזור FIFO מלא, לרבות צילומי מצב מאוחרים. אם צילום מצב מאוחר קובע את היתרה היום, תוצג אזהרה שהוספת ההיסטוריה לא בהכרח משנה אותה. עסקאות באותו יום נוספות אחרי הרשומות הקיימות באותו יום; אין המצאת שעת ביצוע, כי הסכמה שומרת תאריך בלבד. גבול ״היום״ נקבע לפי Asia/Jerusalem.

אחרי השמירה קוראים מחדש את כל ההחזקות הפתוחות, כולל חשבונות שלא השתנו. קריאת הרענון מוגבלת לחמש שניות. כישלון רענון אינו הופך שמירה מאומתת לכישלון, ואינו מבצע כתיבה נוספת. בכרטיס מוצגות כמויות ועלויות קנייה; אין המצאת מחירי שוק או רווח נוכחי.

## בדיקות ושחזור מקומי

```sh
npx vitest run __tests__/chat-transactions.test.ts __tests__/chat-transaction-server.test.ts __tests__/chat-sync-app.test.ts __tests__/investment-mcp.test.ts
python3 scripts/test-chat-transactions-postgres.py
node scripts/preview-chat-review.mjs buy
node scripts/preview-chat-review.mjs sell
node scripts/preview-chat-review.mjs screenshot
```

בדיקת PostgreSQL יוצרת מסד מקומי זמני ומסירה אותו בסיום. היא בודקת הרשאות, אי־שינוי לפני אישור, בידוד משתמשים וסשנים, יכולת אישור, קנייה, מכירה חלקית ומלאה, FIFO, היסטוריה, אישור חוזר, פקיעה, תמימות הסקירה וסמכויות תפקיד מוגבל. קובצי התצוגה נוצרים ב־`output/playwright/` ומשתמשים רק בנתוני הדגמה ללא רשת או כתיבה לתיק אמיתי.
